# dsh-split-pane

[English](README.md) | 中文

## 概述

Web 客户端的中列可以是一个对话，也可以是由多个对话组成的分屏工作区。每一格都是一个独立寻址到某个会话的对话：它自己流式输出、自己接收输入、自己排队消息，也自己应答归属它的 `ask_user_question` 与审批弹窗。分屏可向右或向下拆分且没有固定格数上限，分隔条可拖拽，焦点能在格子间用键盘移动、当前格也能用键盘关闭，布局按会话持久化。

## 安装

```sh
# 从本目录安装
dsh plugin --profile web add .

# 或用路径 / git 规格
dsh plugin --profile web add file:/Users/mac/projects/dsh-split-pane
```

随后重启 `dsh web`。侧边栏的面板列表中，「分屏」条目会出现在「对话」旁边；选中它即可把中列换成分屏工作区。

需要 DeepSeek Harness `0.2.0-rc.2`。本插件在 `peerDependencies` 中声明该范围，且对 DSH 的引用全部是类型导入，因此浏览器包会通过 shell 自身的模块表解析所有共享模块。

## 使用此包

有三个入口，三者结果一致：新增一格，里面是一个**新会话**，且落在你拆分时所在会话所属的工作区里。

**会话头部按钮。** 打开任意对话后，头部右侧的工具栏里、紧挨右侧栏展开按钮的位置有一个分屏控件。点击它会拆分你正在阅读的面板，并打开分屏工作区、聚焦到新会话，可直接输入。

**快捷键。** 两个方向各有一条命令：`Cmd/Ctrl+Alt+S`（`splitPane.new`）向下分屏、`Cmd/Ctrl+Alt+Shift+S`（`splitPane.newRight`）向右分屏；两条都列在快捷键参考面板里，第一条也显示在头部按钮的悬浮提示里。方向必须分成两条命令，因为绑定声明的是物理组合，带不了参数。Linux Web 不设默认键位——浏览器的按键白名单在该平台只放行少数组合，DSH 自带命令同样不给 Linux Web 绑定；可在快捷键参考面板自行指定，也可以按自己的习惯把两个方向对调。

**在格子间移动与关闭。** 只要分屏工作区正在屏上，就有五个命令：Web 上是 `Cmd/Ctrl+Shift+方向键`，桌面端是 `Cmd/Ctrl+Alt+方向键`，把焦点移到该方向的相邻格子；`Cmd/Ctrl+Alt+Backspace` 关闭当前格，由接管其空间的格子继承键盘焦点。相邻按几何位置判定：两格必须共用一条边，只在角上相接的不算；同一方向有多个候选时取最近的一个，距离相同则取重合边更长的一个（宽格右边叠了三格时，落到覆盖它最多的那一格）。焦点移动会把浏览器的输入焦点一并交给目标格的输入框，所以可以直接接着打字；在布局边缘按方向键不会有任何动作，但按键仍归工作区所有，不会变成输入框里的光标跳转。macOS 的 Web 用 `Cmd+Shift` 而不是 `Cmd+Alt`：Chrome 与 Firefox 把 `Cmd+Option+←/→` 用于切换标签页、`Cmd+Option+↑/↓` 用于在工具栏间循环焦点，被浏览器保留的组合根本不会送达页面。Linux（桌面与 Web）不设默认键位，原因见「已知限制」。

**格子自己的分屏控件。** 进入工作区后，每一格的标题行都带向右分屏与向下分屏。任一个都会拆分该格，并在新的半边放入一个新会话。

在全新的空对话上，头部按钮不显示：宿主在对话有内容之前不渲染头部的工具栏槽位。此时可用快捷键或格子内的分屏控件。

侧边栏的面板列表中另有「分屏」条目，与「对话」并列。选中它会把中列换成分屏工作区，但不会新建任何东西；再次选中「对话」条目（或任何其他主面板）即可切回。工作区以当前会话为起点打开，因此进入工作区不会改变用户正在阅读的会话。

每一格都绘制自己的标题行：会话选择器、向右分屏、向下分屏与关闭。会话选择器可把该格改指向任意已有会话，因此格子不会被困在创建时的那一个。关闭某格会把它与兄弟格合并回二者原本占用的空间，最后一格无法关闭——空工作区没有内容可展示。分隔条可拖拽调整占比，并设有下限，保证任一侧都不会窄到不可用。

各格之间不共享状态。每一格持有自己的会话绑定，因此在一格里输入的消息绝不会落到另一格；同一个会话出现在两格时，是同一会话的两个独立视图，而不是被镜像的同一个视图。`ask_user_question` 与审批弹窗都在发起提问的那一格中作答。

布局按「锚定会话」持久化：离开工作区再回来会恢复它，页面重新加载同样如此。若已存储的某一格对应的会话已不存在，该格会变成空面板而不是消失，因此删除一个会话只损失一格的内容，而不会破坏周围的布局。

<a id="understand-the-implementation"></a>
## 实现说明

### 为什么每一格是一个子槽位

`conversation.content` 是一个组件工厂（Component Factory），它的实例继承渲染位置所在的会话；它不接受独立寻址的会话（见 `ui-conversation/README.md` 的 Known Limitations）。因此，要把一个实例寻址到任意会话，就必须有一个 session 作用域的渲染位置——这正是本包以 `scope: 'session'` 声明 `split.pane`、并在 `SessionProvider` 内为每一格渲染一个实例的原因。

本包占用的 `main` 槽位是 root 作用域的 keyed 槽位，因此工作区自身拿不到会话绑定。它通过 `session` 作用域适配器（`ctx.uiSession.adapter.current`）读取当前选择，再为每一格重新寻址。`PaneHost` 承担这份逐格工作：它为所在格的会话保留一份 `sessions.retain()` 引用，并在卸载时释放，因此关闭一格不会影响其他格的 generation。

### 布局模型

`contract/layout.ts` 是纯数据加纯函数，作用于一棵二叉分割树，不含 React 也不含 DOM。每一格用「路径」寻址——从根开始的子节点选择序列——而不是下标，因此移除一格绝不会重排它的兄弟格。占比在构建分割时与分隔条上报拖拽时都会被夹到允许区间内。`reviveTree` 在存储边界校验已存储的树：形状不对的节点被丢弃，会话已消失的格子被置空。

`SplitWorkspace.tsx` 中的 `PANEL_LIMIT` 为 `undefined`，即格数不设上限。停靠工具包（docking kit）的四格上限属于它的 planner 层，从不会到达 `applyOp`，因此自建的分屏工作区不会继承该限制。

### 格子间的键盘导航

方向键的语义建立在几何之上，而不是树的形状上：`paneRects` 用与渲染同一套占比把每个格子量成单位正方形里的一块矩形，`neighborPath` 再据此挑邻居。这样「右边那一格」在任意嵌套深度下都有确定含义，而树上的「下一个兄弟」在嵌套布局里会给出用户意想不到的结果。关闭同样落在模型层：`closeAt` 返回新树与被提升兄弟的第一个格子，因此关闭后焦点落在接管空间的格子上，而不是留在一个地址指向分割节点的陈旧焦点上。

五个命令都只在分屏工作区是屏上那个面板时才动作。其余任何时候——对话视图、设置面板、任何别的面板——它们一律 resolve 成 `pass`，把组合键原样交还：`Cmd+Shift+←/→` 在 macOS 上本就是「选中到行首/行尾」，只在真正存在格子可去的时候才该被接管。

### 为什么格子里画的是输入框，不是 Hero

空会话的 Hero 里挂着 workspace 选择器、品牌标记与 agent preset 控件，这些插槽在 `ui-conversation` 里是 `kind: 'single'`——workspace 与品牌标记是 root 作用域，preset 是 session-maybe 作用域（空会话会解析到 root 那一份）。单例插槽同一时刻只能有一处渲染，于是第二个格子再画一次 Hero，这些条目就会互相争抢同一个 occurrence，每个条目、每个格子报一次 React「maximum update depth exceeded」。因此 `panePhase` 恒把 Hero 标为 `false`：格子画输入框（也就是用户真正要打字的地方），Hero 归主面板独占。

### 文案与本地化

所有可见字符串都存放在 `splitPane` 字典中，并通过标准 `t` 座位抵达组件。标题行控件用同一字典的字符串作为 `aria-label`，因此没有可见文字的格子仍然具备可访问名称。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与延期工作

- **格子渲染的是对话正文，不含会话头部。** 格子展示 transcript 与输入框；常驻头部的导航与视图标签页仍归主面板所有，因为该头部属于 `main.conversation`，不是可复用的工厂。会话标识因此由工作区自己绘制的标题行承载，而不是在每一格里复制一份头部。
- **空格子画的是输入框，不是 Hero。** 空会话的 Hero 携带 root 作用域的单例插槽（workspace 选择器、品牌标记），单例同一时刻只能渲染一处，所以 Hero 留在主面板；格子里是一个可直接输入的输入框，不是那颗大标题。
- **Linux 上没有默认键位。** DSH 的保留键表在 Linux（桌面与 Web 都是）直接拒绝方向键与 Backspace 作为可绑定的物理键，因此方向键与关闭命令只声明 macOS/Windows 的默认值。Linux 用户可以在快捷键参考面板里自行指定（字母或符号键）。
- **空对话上没有头部入口。** 该按钮的席位是头部的工具栏槽位，宿主只在对话有内容后才渲染它；这种状态下可用快捷键或侧边栏的面板条目。
- **保留量随格数增长。** 每一格都持有自己的会话引用与历史流；目前不淘汰屏外格子，因此很宽的布局会按格数消耗实时流。
- **不支持拖拽排布。** 格子由分屏控件创建、由关闭移除；尚不支持把已有格子移动到其他位置。
- **工作区本身不是会话。** 它不携带自己的会话，因此不会出现在会话列表中，其布局以「打开它时的当前会话」作为键。
